# Oglot Usage Guide - Corrected for Jupyter Integration

## Overview

This guide covers the **corrected** integration of oglot with your Doom Emacs setup that uses `org-babel-jupyter-override-src-block`. Oglot enables full LSP support for Org source blocks while maintaining Jupyter's interactive execution capabilities.

## Critical Understanding: Jupyter Override Behavior

### How the Override Works

When you set:
```elisp
(org-babel-jupyter-override-src-block "python")
```

**What happens:**
- Python blocks (`#+begin_src python`) are **executed** using Jupyter
- But they are still **identified as "python"** blocks for editing purposes
- Therefore, you need `org-babel-edit-prep:python`, NOT `org-babel-edit-prep:jupyter-python`

### The Correct Setup

The configuration now correctly defines:
```elisp
(defun org-babel-edit-prep:python (babel-info)
  "Prepare Python source block for editing with Eglot/LSP support."
  (let* ((params (nth 2 babel-info))
         (tangle (alist-get :tangle params)))
    (when (and tangle (not (string= tangle "no")))
      (oglot-org-babel-edit-prep babel-info))))
```

This works for **both**:
- Regular Python blocks
- Jupyter-overridden Python blocks

## The Perfect Jupyter Notebook Workflow in Org Mode

### Quick Start: Single Block Example

```org
#+begin_src python :tangle ./analysis.py :comments link :session py
import pandas as pd
import numpy as np

def load_data(path):
    """Load CSV data with error handling."""
    return pd.read_csv(path)

def analyze(df):
    """Perform basic statistical analysis."""
    return df.describe()

# Test it
df = load_data('data.csv')
result = analyze(df)
print(result)
#+end_src
```

**Workflow:**
1. **Execute with Jupyter**: Place cursor in block, press `C-c C-c`
   - Runs in Jupyter kernel
   - See output immediately below the block
   - Variables persist in session "py"

2. **Edit with LSP**: Place cursor in block, press `C-c '`
   - Opens org-src buffer
   - Oglot activates automatically
   - Full LSP features: completion, diagnostics, navigation
   - Press `C-c '` again to save and return

## Using LSP Features

### When Editing with `C-c '`

#### Intelligent Completion
```python
import pandas as pd

df = pd.read_csv('data.csv')
df.  # <- Type dot and get completions for DataFrame methods
```

#### Type Information
```python
def process(data: pd.DataFrame) -> pd.Series:
    # Hover over 'data' to see it's a DataFrame
    # Hover over return type to see it's a Series
    return data['column'].sum()
```

#### Go to Definition
```python
from mymodule import helper

helper()  # <- Press SPC c d to jump to definition
```

#### Find All References
```python
def important_function():
    pass

# Press SPC c R on function name to find all uses
```

#### Rename Symbol
```python
def old_name():
    pass

# Press SPC c r on old_name to rename everywhere
```

#### Code Actions
```python
import pandas
# Press SPC c a to organize imports (adds 'as pd')

def my_function(x):
    # Press SPC c a to add type hints
    pass
```

### All Available LSP Commands

While in org-src-mode (`C-c '` editing):

| Keybinding | Command | Description |
|-----------|---------|-------------|
| `SPC c =` | Format buffer | Format with Ruff |
| `SPC c h` | Show docs | Documentation in echo area |
| `SPC c H` | Show docs (box) | Documentation in floating window |
| `SPC c d` | Go to definition | Jump to where symbol is defined |
| `SPC c D` | Go to type def | Jump to type definition |
| `SPC c R` | Find references | Find all uses of symbol |
| `SPC c r` | Rename | Rename symbol everywhere |
| `SPC c a` | Code actions | Show available refactorings |
| `SPC c o` | Organize imports | Sort and clean imports |
| `SPC c b` | Go back | Return to previous location |
| `]d` | Next diagnostic | Jump to next error/warning |
| `[d` | Prev diagnostic | Jump to previous error/warning |
| `SPC c x` | List diagnostics | Show all errors in buffer |
| `SPC c X` | Project diagnostics | Show all errors in project |

## Troubleshooting

### LSP Doesn't Activate

**Symptom**: Press `C-c '` but no completions/diagnostics appear

**Check 1**: Verify `:tangle` is set
```org
#+begin_src python :tangle ./code.py :comments link
# This should work
#+end_src
```

**Check 2**: Verify oglot setup
```
M-x +oglot/verify-setup
```

Should show:
```
Oglot enabled modes: (python-mode)
org-babel-edit-prep:python: defined
Jupyter override: active
```

**Check 3**: Test Eglot in regular Python file
```
1. Create test.py
2. M-x eglot
3. Should connect without errors
```

### Jupyter Override Not Working

**Symptom**: Python blocks don't execute with Jupyter

**Check**: Verify override is active
```
M-x +jupyter/verify-setup
```

Should show:
```
ob-jupyter loaded: t
python->jupyter override: YES
Default session: py
Default kernel: python3
```

**Fix**: Make sure override happens AFTER ob-jupyter loads:
```elisp
(after! ob-jupyter
  (org-babel-jupyter-override-src-block "python"))
```

### No Completions from Project Context

**Issue**: Only see completions for current block, not whole project

**Solution**: Use `:comments link` and tangle at least once:
```
1. Add :comments link to block
2. C-c C-v C-t (tangle entire buffer)
3. C-c ' (edit block again)
```

### "Can't Find Tangled File"

**Issue**: Oglot can't locate the tangled file

**Solutions**:
1. Make sure `:tangle` path is absolute or relative to org file:
   ```org
   #+begin_src python :tangle ./src/code.py  # Relative to org file
   #+end_src
   ```

2. Create directory if it doesn't exist:
   ```bash
   mkdir -p src
   ```

3. Tangle manually first:
   ```
   C-c C-v C-t
   ```

### Slow LSP Performance

**Issue**: Eglot is slow in org-src buffers

**Solutions**:
1. Reduce basedpyright type checking:
   ```elisp
   (setq-default eglot-workspace-configuration
                 '(:basedpyright
                   (:analysis (:typeCheckingMode "basic"))))  ; Instead of "recommended"
   ```

2. Disable certain LSP features:
   ```elisp
   (setq eglot-ignored-server-capabilities
         '(:hoverProvider
           :documentFormattingProvider
           :documentHighlightProvider))  ; Add more if needed
   ```

3. Use project-level tangling (not block-level):
   ```org
   #+PROPERTY: header-args:python :tangle ./main.py :comments link
   ```

### 5. Documentation Best Practice

Combine prose, code, and results:

```org
* Data Cleaning

We remove outliers using the IQR method. Values outside
1.5 × IQR are considered outliers.

#+begin_src python :tangle ./src/clean.py :comments link :session main
def remove_outliers(df, column):
    """Remove outliers using IQR method."""
    Q1 = df[column].quantile(0.25)
    Q3 = df[column].quantile(0.75)
    IQR = Q3 - Q1
    
    lower = Q1 - 1.5 * IQR
    upper = Q3 + 1.5 * IQR
    
    return df[(df[column] >= lower) & (df[column] <= upper)]
#+end_src

Let's test it on our dataset:

#+begin_src python :session main :results output
original_size = len(df)
df_clean = remove_outliers(df, 'value')
removed = original_size - len(df_clean)

print(f"Removed {removed} outliers ({removed/original_size*100:.1f}%)")
#+end_src

#+RESULTS:
: Removed 42 outliers (4.2%)
```
